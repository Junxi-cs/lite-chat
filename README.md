# lite-chat（极简 AI 对话应用）

一个用于**参考与学习**的极简 AI 对话小项目。它只做最基础的一件事：让你可以和大模型聊天。

## 特点
- **零依赖**：只用 Python 标准库，无需 `pip install` 任何第三方包。
- **两种对话模式**：
  - **外部 API**：填 API Key 接入 OpenAI 等兼容接口。
  - **本地模型**：对接本机部署的模型（如 LM Studio / Ollama），无需 Key。
- **流式输出**：回复以打字机方式逐字显示。
- **极简设计**：仅文本对话，无历史管理、无用户系统、无多模态，方便读懂源码。

## 快速开始

### 方式一：一键启动
双击 `launcher.bat`，稍候浏览器会自动打开 http://127.0.0.1:8000 。

### 方式二：命令行
```bash
cd 项目目录
python app.py
```
然后浏览器访问 http://127.0.0.1:8000 。

## 使用说明
1. 打开页面后，在顶部选择对话模式。
2. **本地模型**：先在 LM Studio 中加载模型并开启 Local Server（默认地址 `http://127.0.0.1:1234`）。在「接口地址」填入该地址（结尾带不带 `/v1` 都可以，程序会自动补全）。填好地址后**模型会自动探测并选中**，无需任何点击，界面底部会显示「当前模型：xxx」。
3. **外部 API**：填接口地址（如 `https://api.openai.com/v1`）与 `sk-...` 密钥。填好地址与 Key 后模型同样自动探测选中。注意：外部服务通常提供较多模型，自动选中的是列表里第一个非嵌入（embedding）模型，未必是你想要的那个——如需指定，见文末补充说明。
4. 在输入框输入消息，回车（或点「发送」）即可，回复以打字机方式逐字显示。

## 文件结构
- `app.py` —— 后端，把请求转发到任意 OpenAI 兼容接口，并以 SSE 流式返回。
- `index.html` —— 前端页面（由 `app.py` 读取并返回）。
- `launcher.bat` —— Windows 一键启动脚本。

## 功能详解（补充参考）

> 以下是对上述功能的展开说明，供阅读源码与排查问题时参考。

### 1. 两种模式，统一走 OpenAI 兼容协议
应用本身**不内置任何模型**，只做“中转”：把前端的消息转发给任意 **OpenAI 兼容**的 `/v1/chat/completions` 接口。因此本地模型（LM Studio / Ollama / vLLM 等）和各大云平台（OpenAI、OpenRouter 等）只要暴露 OpenAI 兼容接口，都能直接用。两种模式的唯一区别是**是否填 API Key**：本地通常留空，外部必须填。

### 2. 接口地址自动规范化
你填写的地址会被统一处理成以 `/v1` 结尾，避免拼出错误路径：
- `http://127.0.0.1:1234` → `http://127.0.0.1:1234/v1`
- `https://api.openai.com` → `https://api.openai.com/v1`
- 已带 `/v1`（如 `https://api.openai.com/v1`）则原样使用

对应代码：`app.py` 中的 `normalize_base()`，被 `/api/chat` 与 `/api/models` 共用。

### 3. 模型自动探测（无需手动填写、无需点击）
- 当「接口地址」填写（或切换模式、填写 Key）后，前端会自动请求该服务的 `/v1/models`，拿到可用模型列表。
- **自动选用规则**：优先选**第一个非嵌入（embedding）模型**。因为 embedding 模型不能聊天，且部分服务会把 embedding 模型排在列表首位，直接选它会“聊不起来”。
- 选中的模型名显示在界面底部「当前模型：xxx」，你无需也不能手动修改（保持极简）。
- 兜底：即便前端没探测到，发送时后端 `_handle_chat` 也会再自动探测一次；若仍拿不到，会给出明确错误而不是静默无回应。

### 4. 流式输出（SSE）
- 请求时带 `stream: true`，上游以 Server-Sent Events 逐块返回。
- 后端**边读边转发**（`_forward_line` 只抽取 `choices[].delta.content`），前端把每个分片追加到气泡里，形成打字机效果。
- **多轮上下文**：前端维护一个 `messages` 数组（用户/助手轮流追加），每次发送都带上完整历史，因此支持多轮对话。该数组仅存在于浏览器内存，刷新页面即清空——这是“对话”本身需要的最小能力，不是历史管理功能。

### 5. 错误处理（避免静默失败）
- **上游非 200**（地址错、Key 错等）：直接把错误原因转发成红色错误气泡。
- **上游返回 200 但不是真正的 SSE 流**（例如 LM Studio 收到错误路径时返回 `200 + 错误页`）：识别后报“上游未返回流式数据”，而不是默默无回应。
- **自动探测模型失败**（如 Key 错误导致 401）：明确提示“自动探测失败：HTTP 401…”，帮助你定位是地址/Key 问题，而不是误报“未指定模型”。

### 6. 一键启动与自动开浏览器
- `launcher.bat`：双击即启动服务，并自动打开浏览器到 http://127.0.0.1:8000。
- `app.py` 启动后也会用 Python 自带的 `webbrowser` 在 1.5 秒后尝试打开浏览器（无图形界面时静默跳过，不影响服务）。

### 7. 零依赖与隐私
- 后端只用 Python 标准库（`http.server` / `urllib` / `webbrowser`），无需 `pip install` 任何第三方包。
- 所有请求都在**你本机**完成：浏览器 → 本机 `app.py` → 目标大模型服务。API Key 仅用于转发请求，**不写入任何文件、不落盘、不对外暴露**。
- 无用户系统、无对话历史持久化、无多模态输入——便于阅读源码、作为学习示例。

### 8. 已知限制
- **外部 API 的模型选择**：若提供商返回大量模型，自动选中的是“第一个非嵌入模型”，不一定是你想用的那个。如需固定某模型，可在 `app.py` 的 `_handle_chat` 中直接给定 `model`，或确保提供商支持 `/models`。
- **不支持 `/models` 的提供商**：少数云厂商不暴露 `/models` 接口，自动探测会失败；这种情况同样需要在代码中显式指定模型名。
- **上下文仅存内存**：刷新页面即丢失（设计如此，非 bug）。
- **单用户单会话**：当前为简单实现，不支持并发多会话 / 多用户。
